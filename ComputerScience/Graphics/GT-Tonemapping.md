## 출처

[톤 매핑](./Tone-Mapping.md) 비교표에서 "스타일라이즈 프로젝트에 자주 쓰인다"고만 짧게 언급하고
넘어갔던 GT 톤매퍼를 별도로 깊게 파고든 문서. 컴투스 TA실 발표(유튜브, `watch?v=UwXWFrjVWd4`)의
발표자가 "개인적으로 스타일라이즈 프로젝트가 많아서 GT 톤매퍼를 자주 쓴다"고 언급한 게 계기였다.

## 정의

GT 톤매퍼는 소니의 레이싱 게임 "그란 투리스모" 시리즈를 개발하는 폴리포니 디지털의 우치무라
하지메(内村肇)가 CEDEC 2017 발표 "HDR theory and practice"에서 공개한 필름형 톤 매핑 곡선이다.
ACES나 Reinhard처럼 "곡선 모양이 고정된" 톤매퍼와 달리, **여섯 개의 파라미터**로 토(어두운
영역)·선형 구간(중간 톤)·숄더(밝은 영역)의 길이와 기울기를 아티스트가 직접 조절할 수 있게
설계됐다 — "그란 투리스모"라는 이름 그대로, 게임 커뮤니티에서는 짧게 "GT 톤매퍼"라 부른다.

## 요약

GT 톤매퍼의 핵심은 "하나의 정해진 필름 룩"이 아니라 **"필름 룩을 만드는 다이얼 세트"**를 제공한다는
점이다. 파라미터를 어떻게 두느냐에 따라 ACES에 가까운 강한 대비도, Neutral에 가까운 밋밋한 톤도
모두 이 곡선 하나로 표현할 수 있다 — 그래서 프로젝트마다 원하는 룩이 뚜렷이 다른 스타일라이즈
프로젝트에서 "톤매퍼를 바꾸는 대신 파라미터만 바꾼다"는 워크플로우가 가능해진다.

## 상세

### 왜 "토 / 선형 / 숄더" 세 구간을 따로 취급하는가

[톤 매핑](./Tone-Mapping.md)에서 다룬 대로, 대부분의 필름형 커브는 어두운 영역(토)·중간
톤(선형)·밝은 영역(숄더)이 서로 다른 성질을 갖는다. ACES 같은 근사식은 이 세 구간을 **하나의
수식**(유리함수 하나)으로 뭉뚱그려 표현하기 때문에, 그 수식의 모양 자체를 바꾸지 않고는 "선형
구간만 좀 더 길게" 같은 미세 조정이 어렵다. GT 톤매퍼는 반대로 세 구간을 **처음부터 서로 다른
수식**(토는 거듭제곱 곡선, 선형 구간은 진짜 직선, 숄더는 지수함수 롤오프)으로 만들고, 그
구간들이 만나는 경계와 기울기를 파라미터로 노출한다 — "구간을 나눠서 각자 원하는 모양으로
빚은 뒤 이어붙인다"는 접근이다.

### 여섯 개의 파라미터

| 파라미터 | 의미 |
|---|---|
| `P` | 최대 표시 밝기(피크 화이트) — 이 값 이상은 완전한 흰색으로 수렴 |
| `a` | 대비(contrast) — 토/숄더 구간이 얼마나 가파르게 꺾이는지 |
| `m` | 선형 구간이 시작되는 지점(회색값 기준 비율) |
| `l` | 선형 구간의 길이 — 길수록 "원본 그대로"인 중간 톤 범위가 넓어짐 |
| `c` | 블랙 타이트니스 — 토 구간에서 어두운 값을 얼마나 빠르게 압축할지 |
| `b` | 블랙 오프셋 — 완전한 검정 대신 살짝 들어올린 최소값을 줄지 |

이 여섯 값 중 실무에서 체감이 가장 큰 건 `a`(대비)와 `l`(선형 구간 길이)이다. `a`를 올리면
ACES처럼 대비가 강한 "시네마틱" 톤에 가까워지고, `l`을 늘리면 Neutral처럼 원본 색을 더 오래
그대로 보존하는 쪽에 가까워진다 — 즉 GT 톤매퍼의 파라미터 공간 안에 ACES와 Neutral의 "느낌"이
어느 정도 포함되어 있다고 볼 수 있다.

### 세 구간이 실제로 이어지는 방식

각 구간의 수식은 다음과 같은 역할을 한다(정확한 계수 유도는 CEDEC 슬라이드 참고, 여기서는
구조만 짚는다).

1. **토(toe)**: `x`가 `m`보다 작은 어두운 영역에서 거듭제곱 곡선(`x^c` 꼴)을 써서 블랙 레벨을
   조인다. `c`가 클수록 어두운 값이 더 빠르게 눌린다.
2. **선형(linear)**: `m`부터 `m + l0`(선형 구간 길이)까지는 기울기 `1`에 가까운 **진짜 직선**을
   쓴다 — 이 구간에서는 입력 대비가 거의 왜곡 없이 그대로 출력된다. 사람 눈이 가장 민감한
   중간 톤을 왜곡하지 않으려는 의도다.
3. **숄더(shoulder)**: 선형 구간이 끝나는 지점부터는 지수함수 형태로 `P`(피크 화이트)에
   점근하도록 부드럽게 눌러준다 — 아무리 밝은 입력이 들어와도 `P`를 넘지 않는다.

세 구간의 경계에서 값과 기울기가 매끄럽게 이어지도록(smoothstep 가중치로 블렌딩) 설계되어 있어,
파라미터를 바꿔도 구간 경계에서 눈에 띄는 꺾임이 생기지 않는다.

## 질문

- **Q. GT 톤매퍼와 Hable의 "필름형(Uncharted 2)" 커브는 뭐가 다른가?**
  A. 둘 다 토/선형/숄더 구조를 가진 필름형 커브라는 점에서 계열이 같고, GT 톤매퍼는 사실 이
  계열의 발전형에 가깝다. 가장 큰 차이는 파라미터화 방식이다 — Hable의 원조 Uncharted 2 커브는
  `A`(숄더 강도)·`B`(숄더 선형성)·`C`(숄더 각도)·`D`(토 강도)·`E`(토 오프셋)·`F`(토 각도) 여섯
  개를 쓰지만 각 파라미터가 곡선의 미분 계수처럼 추상적이라 직관적으로 조절하기 어렵다는 평이
  있었다. 우치무라는 이 경험을 바탕으로 "선형 구간의 시작 위치·길이"처럼 더 직관적인
  파라미터(`m`, `l`)로 재구성했다 — 결과물의 성질은 비슷하지만 다이얼을 돌렸을 때 예측 가능성이
  더 높다는 게 GT 톤매퍼가 강조하는 개선점이다.

- **Q. 왜 URP는 GT 톤매퍼를 기본 제공하지 않나?**
  A. URP의 `Tonemapping` 오버라이드는 `None`/`Neutral`/`ACES` 세 가지만 노출한다 — 둘 다
  "파라미터 없이 바로 쓸 수 있는" 톤매퍼인 반면, GT 톤매퍼는 여섯 파라미터를 프로젝트마다
  아티스트가 직접 맞춰야 하는 도구에 가깝다. Unity 입장에서 기본 볼륨 오버라이드에 여섯 개의
  슬라이더를 노출하는 대신, "필요한 프로젝트가 직접 커스텀 셰이더로 들여오라"는 쪽을 택한 것으로
  보인다 — 실제로 [LUT PS](../URP_PostProcessing/LUT-PS.md)에서 다룬 것처럼, URP에서 GT
  톤매퍼를 쓰려면 `Lut Builder Ldr/Hdr PS`의 톤 매핑 계산 부분을 직접 교체해야 한다.

- **Q. 파라미터를 어디서부터 튜닝을 시작해야 하나?**
  A. 우치무라의 발표에서 예시로 자주 인용되는 기본값은 `P=1.0, a=1.0, m=0.22, l=0.4, c=1.33,
  b=0.0`이다(노출 1.0 기준). 이 값에서 시작해 `a`(대비)와 `l`(선형 구간 길이) 두 개만 먼저
  움직여보는 게 체감이 가장 빠르다 — 나머지 네 파라미터는 미세 조정용으로 남겨두는 경우가 많다.

## 예시 코드

```hlsl
// Uchimura(GT) 톤매퍼 — CEDEC 2017 발표 자료를 바탕으로 커뮤니티에 널리 퍼진 GLSL/HLSL 포팅.
// 정확한 계수는 원 발표 슬라이드 기준으로 재검증할 것 — 구조를 이해하기 위한 참고용 코드다.
float3 Uchimura(float3 x, float P, float a, float m, float l, float c, float b)
{
    float l0 = ((P - m) * l) / a;
    float S0 = m + l0;
    float S1 = m + a * l0;
    float C2 = (a * P) / (P - S1);
    float CP = -C2 / P;

    float3 w0 = 1.0 - smoothstep(0.0, m, x);          // 토 구간 가중치
    float3 w2 = step(S0, x);                           // 숄더 구간 가중치
    float3 w1 = 1.0 - w0 - w2;                          // 선형 구간 가중치

    float3 T = m * pow(max(x / m, 1e-6), c) + b;        // 토(toe) — 거듭제곱 압축
    float3 S = P - (P - S1) * exp(CP * (x - S0));       // 숄더(shoulder) — 지수 롤오프
    float3 L = m + a * (x - m);                         // 선형(linear) — 진짜 직선

    return T * w0 + L * w1 + S * w2;                    // 세 구간을 가중치로 이어붙임
}

// 기본값 예시(우치무라 CEDEC 2017 슬라이드 기준)
// Uchimura(hdrColor, 1.0, 1.0, 0.22, 0.4, 1.33, 0.0)
```

## 실무

실무에서 GT 톤매퍼는 특히 애니메이션풍·카툰풍 비주얼처럼 "ACES의 강한 필름 대비는 과하지만,
Neutral만으로는 밋밋하다"고 느끼는 프로젝트에서 절충점으로 자주 선택된다. Unreal Engine
커뮤니티에서도 커스텀 포스트 프로세스 머티리얼로 이식하는 사례가 많고, Shadertoy·GitHub에
공개된 구현체가 여러 개 돌아다닐 만큼 인지도가 높다. 다만 파라미터가 많다는 건 "아트 디렉터가
매 프로젝트마다 값을 다시 잡아야 한다"는 뜻이기도 해서, 여러 프로젝트를 동시에 지원하는
조직에서는 프로젝트별 프리셋(파라미터 조합)을 미리 몇 개 만들어두고 거기서 시작하는 방식이
실무적으로 효율적이다.
